大模型的上下文（Context Window）

LLMcontext-windowpromptattention
日期：2026-09-05 · 深度：standard · 受众：自我学习者
大模型的"上下文（Context）" = 一次推理中，模型能看见并据以生成下一段文本的全部输入。它通常被切成 tokens，总长度受 context window 限制。它是模型的"短期舞台"，不是"长期记忆"。

个人理解

我每次讲 LLM 上下文都忍不住要拽一句"舞台 vs 记忆"的类比——因为这是最容易混淆的事：

把 LLM 想象成一个没有记忆的演员。每次TA 走上台前，灯光亮起的那一刻，导演（也就是调用方）要递给TA一张大纸，这张纸就是 context window。纸的容量是有限的（8k、32k、200k token 不等）。纸上的内容决定这次表演能演得多好——但TA 演完谢幕后，下一次再上台时完全不记得上次演过什么。

所以"上下文"是个动词性概念：它指的是本次推理的输入边界，而不是某种持久存储。系统提示词、历史消息、工具返回、用户当前问题、检索召回的片段——所有这些加在一起，必须装进这个窗口。

一旦你把这个框架立起来，很多"AI bug"立刻就有了解释：模型"忘了对话开头说过什么"是因为它本来就没记忆，是上下文塞不下；模型"前后矛盾"是因为不同 token 之间注意力被稀释，不是"AI 学坏了"。

核心机制

  • 按 token 计，不按字符计。1 token ≈ 0.75 个英文单词 ≈ 1.5 个汉字。模型最小感知单位是 token，不是字符也不是词。
  • 有硬上界。当前主流模型 8k–200k token 不等；超出窗口会被截断或报错。
  • 输入+输出都计费。输入便宜，输出贵（~5x），所以"让模型写长 prompt"和"让模型写短答案"是两个 trade-off。
  • 注意力随距离稀释。长上下文中"迷失中间 (lost in the middle)"现象——窗口开得越大，每个 token 分到的注意力越稀，模型对中段细节的引用显著下降。
  • 可被显式工程化。system prompt、消息摘要、检索增强 (RAG)、工具返回筛选……都是"上下文工程 (context engineering)" 的具体手段。
  • 状态机语义。一次推理完成后，上下文窗口里的内容默认全丢（除非你自己存到外部）。

一个具体的应用场景

场景：让 Claude 总结一份 80 页 PDF 报告（约 35k tokens）。直接扔进去，模型回答时经常丢中间内容。

解法：先做"层级摘要"——把 PDF 切块，每块先要 LLM 抽出 200 字的章节摘要，所有章节摘要加起来不到 5k token，然后再用 5k 摘要去回答原始问题。

# 伪代码：层级摘要解法
chunks = split_pdf(pdf, by='page', chunk_size=1000)   # ~35 chunks
summaries = []
for c in chunks:
    s = llm.complete(
        system="用 200 字总结这一段的关键词和结论",
        user=c
    )
    summaries.append(s)

# 把"信息密度高"的摘要塞回上下文
final_answer = llm.complete(
    system="基于以下章节摘要回答问题。",
    user=f"问题：{question}\n\n章节摘要：\n" + "\n\n".join(summaries)
)

塞进上下文的 token 变少了（35k → 5k），但回答质量可能反而更好——因为模型现在看到的是"精炼版"，而不是 80 页噪音。这就是"上下文工程"的核心理念：模型好坏不在窗口大小，在窗口里装的是什么。

混淆与边界

  • 误解：上下文窗口 200k = 模型能精确用满 200k。 正解：超长上下文中模型对中后段细节的引用显著下降（"lost in the middle" 在 2023 的 "Lost in the Middle" 实验里被系统量化过）。窗口大 ≠ 记得全。
  • 误解：清空对话 = 模型"失忆"。 正解：清空只清当前会话的上下文；真正的"记忆"看你怎么设计 system prompt + 外部长期存储。
  • 误解：提示词 (prompt) ≠ 上下文。 正解：提示词是上下文的一部分；上下文还包括历史消息、工具返回、system 指令、检索片段等所有 token。
  • 误解：长上下文是 RAG 的替代品。 正解：两者解决不同问题。RAG 把"找得到"的事情自动化，长上下文主要负责"装得下"。在生产里它们往往配合使用：先 RAG 召回 top-k（几千 token），再让模型基于这批摘要在长上下文里写答案。

自检问题

  1. 【复述】用一句话讲清楚"上下文窗口"和"对话历史"的区别？
  2. 【对比】长上下文 (long context) 和 RAG 都试图"让模型看到更多资料"，它们各自的代价是什么？
  3. 【应用】你最近做的一个 LLM 任务里，输入的 token 大概有多少？哪段最占空间？能不能砍掉？
  4. 【判断】什么时候应该压缩上下文（摘要 / 截断），什么时候应该扩大窗口？
  5. 【延伸】如果是 Agent，它的"短期舞台（context）"和"长期记忆"是怎么分界的？想想每次 loop 跑完后哪些 token 应该被忘掉？
