这三件事不在同一层：LLM Context 是 Agent 的"短期舞台"；Agent 是用这个舞台跑循环的程序；Skill 是教会程序"怎么工作"的手册。下文把它们的边界、共同点、如何相互影响画清楚。

上下文如何影响 Agent 的工作

这件事很多人低估了。Agent 的"工作质量"几乎完全被两件事决定：决策点（由 LLM 完成）和上下文里装的是什么。而 LLM 在决策时只能看见上下文窗口里的 token——所以上下文就是 Agent 的"短期认知上限"。

三条具体影响

  1. 窗口大小 → 决策时的"信息完备度"。上下文越大，能装下的对话历史、工具返回、文档片段越多。但 Lost in the Middle 这篇论文已经量化过——窗口变大不代表引用变准。
  2. 上下文内容 → 决策时的"行为约束"。同样的 Agent + 同样的任务，system prompt 改了"语气/工具使用偏好/排除项"，行为可以完全变。System prompt 是上下文里的"宪法"段，最先决定 LLM 风格。
  3. 上下文整理 → 决策的"成本与速度"。塞得越多，每次推理的 token 计费越高、速度越慢。生产环境的 Agent 必须主动整理上下文——删过时消息、摘要长工具返回、丢弃低价值的中间结果。

一个具体例子

同一个 Agent 任务"调研最近 30 天的 5 个热门 AI Agent 仓库"，给三种不同的上下文：

上下文结果
空 system prompt + 用户原话Agent 自由发挥，可能跑 5+ 次网络搜索，输出冗长
System prompt 规定"最多 3 次工具调用，输出 ≤ 200 字"Agent 收敛很快，输出精炼
System prompt 加上"references/search-strategy.md 是一份搜索策略手册"Skill 加载后，Agent 走专业化路径，质量显著提升

三件事的区别**只来自上下文**，模型权重、工具集、循环结构都没变——这就是"上下文决定 Agent 上限"最直接的证据。

Skill 如何沉淀可复用的任务知识

如果说系统提示是"宪法"，那 Skill 就是"手册"——它把某一类任务的经验沉淀下来，下次再遇到相似任务直接调用。这里"沉淀"有四个层次：

层次沉淀位置谁来管理复用场景
本次会话 对话历史（context 里） 用户 + Agent 一起 当前任务
系统提示 每次启动加载 用户手写 整个项目 / 整个用户
Skill .workbuddy/skills/<name>/SKILL.md Agent + skill-creator 匹配 description 的任何任务
外部知识库 (RAG) 向量库 / 文档系统 检索服务 运行时召回特定事实

Skill 的位置介于"system prompt"和"知识库"之间——它有触发逻辑（像 system prompt 一样自动加载），又装得下结构化工作流（像知识库一样可被设计）。它特别适合沉淀这三类知识：

  1. 重复性工作流。"每周把 GitHub issues 整理成 Excel 表"——这种活儿写一次 Skill，下次说一句话就触发。
  2. 领域规范。"我们团队的代码 review 必须看 XX"——Skill 提醒 Agent 别忘。
  3. 专家经验。"翻译时要保留专业术语，不要意译"——Skill 把人类经验做成可检的工作流。

Skill 沉淀知识的生命周期

一次性投入 ──▶ 长期复用 ──▶ 持续迭代
   │              │              │
   │              │              └─ 用户反馈驱动 SKILL.md 修订
   │              └─ description 触发 → Level 2 加载 → 完成任务
   └─ 写 SKILL.md + references/ + scripts/

收益点：
  写一次 → 任何项目/会话都能用 → 团队新人也能用
  改一处 → 全部场景同步生效

维度LLM ContextAgentSkill

设计目标"装什么""决定下一步""遇到 X 时按 Y 做"
主要操作填满、压缩、检索推理、调用、观察加载、引用、迭代
出错信号lost in the middle、截断无限循环、累积错误触发词不准、description 模糊

一句话串起来

Skill（沉淀知识，文件形式）→ 触发后加载进 Agent 的 Context（短期舞台）→ Agent（用 context 做决策、跑循环、调工具）→ 工具结果回填到 Context → 决定下一步 → 直到结束。

把这三者当成一个整体看：Skill 写"怎么做"，Context 决定"能看见什么"，Agent 负责"决定做什么"。三者配合好，AI 应用就稳；任意一个失衡，bug 就来。
