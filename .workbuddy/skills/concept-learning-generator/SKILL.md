# Concept Learning Generator — 概念学习资料生成 Skill

面向**任意概念**的通用学习资料生成器。给一个概念名，产出结构统一、来源可核查、可视化讲解到位的独立学习资料。

> 本 Skill 不是为 Agent / 上下文 / Skill 这三个概念写的一次性提示词。新增任意概念时，只需提供概念名，重复 Step 1–5 即可。

---

## 一、触发判断

**若用户给的是一个名词/概念/术语，且期待一份"资料"而非一句话答案，则使用本 Skill。**

| 应该触发 | 不应触发 |
|---|---|
| "用 concept-learning-generator 学习一下 **Agent**" | "怎么用 git rebase" —— 工具用法 |
| "帮我生成 **大模型的上下文** 的学习资料" | "帮我修这个 bug" —— 调试任务 |
| "我想搞懂 **Skill** 在 AI Agent 里是什么" | "做一份 PPT" —— 文件生成任务 |
| "给我一份带来源的 **CAP 定理** 学习卡片" | "现在几点了" —— 一句话事实查询 |
| "用 **贝叶斯定理** 出一份学习材料" | "把这个 PDF 转成 Word" —— 格式转换 |

判断标准：**用户的诉求是不是"理解一个概念"。** 是 → 用本 Skill。

---

## 二、输入信息 (Input)

调用时尽量收集以下信息。**缺省项可合理假设，但必须在生成物中标注"假设"。**

| # | 字段 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| 1 | **概念名称** | ✅ 必填 | — | 如 Agent、大模型的上下文、Skill。中英文均可，建议同时记录英文/别名 |
| 2 | 学习视角 / 背景 | 否 | `自我学习者` | 如"从 AI Agent 工程角度""面向大三学生""用于面试复习" |
| 3 | 目标产出格式 | 否 | `html` | `html`（默认，独立可打开）/ `md` |
| 4 | 输出路径 | 否 | `learning-materials/<slug>.html` | slug 为概念英文/拼音短名，小写中划线 |
| 5 | 已有偏好 | 否 | 配色：浅色主题；语言：中文；可视化：由模型判断概念难点后自行决定 | 配色、语言、是否要可视化讲解、偏好哪类图 |

**处理原则**：

- 用户没说的按默认值走，并在资料顶部"元信息"里显式写出 `假设：xxx`。
- 概念是多义词 / 有歧义时，**先在资料开头一句话消歧**，说明本资料取哪个义项。
- 用户给的 slug 若与已有文件重名，追加 `-2` 或改用更精确的 slug，并告知用户。

## 三、生成步骤 (Procedure)

> **核心理念：先找真实来源，再写自己的话。禁止凭空编造引用链接。**

### Step 1 — 拆解与检索 (Research first)

先用 `WebSearch` 检索该概念的权威、可核查来源。**优先顺序**：

1. **官方文档 / 官方工程博客**（如 anthropic.com、官方 docs、官方 GitHub 仓库）
2. **经典论文**（arXiv、顶会论文；记录编号）
3. **领域公认的技术博客 / 综述**（仅作补充与通俗化）

操作要点：

- **记录每条来源的真实 URL 与标题**，稍后原样写入"参考来源"。不要凭记忆写 URL。
- 对**不确定是否仍有效**的链接，用 `WebFetch` 验证一次再写进去。
- 概念太新或来源稀少时，**明确标注**："公开可靠来源有限，以下为基于既有资料的推论"。
- 检索到的关键事实，在正文里用 `[来源 N]` 标注，N 对应文末"参考来源"编号。

### Step 2 — 结构化组织 (Organize)

按"四、输出结构"把内容组织成 **9 个板块**（其中"可视化讲解"专门用于图形化核心概念/难点，规则见第四节）。

- 每个板块都要**用自己的话写**，不得整段照搬任何来源或 AI 对话原文。
- 引用处用 `[来源 N]` 标注。
- 区分三类内容：**官方事实**（标来源） / **他人观点**（标来源 + 注明是观点） / **本人理解**（写在"个人解释"板块）。

### Step 3 — 撰写个人解释 (Personalize)

"个人解释"板块**必须以第一人称写**，体现学习者自己的理解：

- 用"我理解它其实是……""它和 Y 最大的不同是……""我一开始把它误当成……"这类句式。
- 这部分可由 AI 起草，但必须**留出供本人修改的空位或明显标注**（例如 `<!-- 人工复核区：请用自己的话改写 -->` 或页面上标注"🔍 待人工复核"徽章），便于人工复核。

### Step 4 — 生成文件 (Generate)

**若输出 HTML**：

- **独立 HTML**：内联 CSS（**不依赖外部样式表**，便于直接双击打开），使用清晰的卡片/分区布局，浅色主题，中文排版。
- 顶部放**概念名、一句话定义、生成日期**。
- "参考来源"用 `<ol>` 列出，每条含**可点击真实链接 + 一句话说明**。
- 生成"可视化讲解"板块：按该模块规则，为最适合用图讲的核心概念/难点画 **1–3 张图**。
  - 优先 **纯 HTML + 共享/内联 CSS**（div 条、进度条、表格、网格、内联 SVG）——离线双击即可看。
  - 需要复杂拓扑时才引入 **Mermaid**（CDN `https://cdn.jsdelivr.net/npm/mermaid`）。
  - **每张图都必须有文字兜底**，防止离线 / CDN 失效时读者看不懂。

**若输出 md**：同样包含 9 个板块；可视化部分用 Markdown 表格 + 代码块 ASCII 图（因为 md 不能保证渲染 Mermaid）。

### Step 5 — 自检 (Self-check)

执行"六、自检要求"清单。**不通过则修正后再交付。**

## 四、输出结构 (Output structure)

每份资料必须包含以下板块（HTML 中用 `<section>` 承载）：

1. **学习目标** — 学完这份资料后，应能回答/做到什么（**3 条左右**）。
2. **核心问题** — 围绕该概念最该搞清楚的 **2–4 个问题**。
3. **个人解释** — 第一人称、用自己的话概括"它到底是什么"。
4. **核心机制 / 组成** — 它由哪些部分构成、如何运作（可用列表 / 图示）。
5. **可视化讲解 (Visualize)** — 见下方专节。
6. **应用场景** — 一个具体的例子（说明**谁、在什么环节、用它解决了什么**）。
7. **易混淆 / 使用边界** — 常与什么概念搞混、什么情况下不适用或会失效。
8. **自测问题** — 3–5 道简答题/选择题/应用题，附答案或答题要点（见下方规范）。
9. **参考来源** — 真实、可核查的链接列表，**带编号**。

---

### 5.1 可视化讲解模块（务必遵循）

> 这是本 Skill 的专属讲解模块，目标是呈现"文字讲不清、图一看就懂"的核心概念 / 难点 / 易混淆点。

**数量**：全篇图表控制在 **1–3 张**，宁缺毋滥。

**触发判断**：只有当判断"该点存在**结构 / 流程 / 对比 / 定量 / 时空**维度，且比纯文字更利于理解"时才画。
- 核心概念、难点、易混淆点里"值得画"的就画。
- **文字能说清的不必硬凑。**

**选型（按内容选最合适的，可混用）**：

| 内容类型 | 推荐图形 |
|---|---|
| 组成 / 结构 | 结构图分区、堆叠条 |
| 流程 / 步骤 / 生命周期 | 流程图箭头、时间线 |
| 大小、占比 / 对比 | 条形、进度条、仪表盘 |
| 概念间关系（依赖/因果/包含） | 关系图（节点 + 连线） |
| 连续变化 / 分布 / 陷阱 | 曲线区间（如"位置–利用率"曲线） |

**实现（必须离线可打开）**：
- **默认纯 HTML + CSS**（不依赖外部资源，双击即可看）。
- 拓扑复杂时才用 **Mermaid**（加载慢、不可控、离线有兜底）。
- **禁止**只用一张外链图片或 base64 大图充当"可视化"。

**文字兜底（强制）**：
- 每张图配 `class="viz-caption"` 的一句话图说。
- 若图依赖 Mermaid / JS / 外链，**必须再附一行纯文字说明**，保证离线 / CDN 失效时读者仍能从文字看懂"这张图在说什么"。

**数据诚实**：
- 图中出现的数字/占比/坐标**必须真实可溯源**（对应正文或 `[来源 N]`）。
- 示意性数字**显式标注"示意"**，不得把臆造数值当事实。

**可交互（可选加分项）**：
- 对阈值/滑块/展开等可用**轻量原生 JS**（如 `<input type="range">` + 内联脚本），**不依赖框架**。
- 无交互也完全合格。

**落位**：紧跟在"核心机制"对应讲解之后，作为独立 `<section>`，编号连续。

---

### 5.2 自测题出题规范（务必遵循，确保可真正用于自我测验）

- **题型组合**：简答题 + 选择题 + 应用题（"请描述/举例"类）。
- **覆盖维度**：①概念辨析（与易混淆概念的区别）；②核心机制（组成/运作）；③具体应用场景；④风险与边界（何时失效 / 常见失败模式）。
- **答案格式**：
  - 每题配套答案或答题要点；
  - 选择题给出**正确选项并简述理由**；
  - 答案置于 `<details>` **折叠区**，便于先自测再看；
  - 应用题给"答题要点"而非单一标准答案。
- **语言**：题干与答案用中文，可保留英文术语（如 Planning / Tool Use / Workflow）。

## 五、资料来源要求 (Source requirements)

- **禁止伪造**：不得编造 URL、论文编号、作者，或"据说某大厂说过"。
- **可核查**：每条来源必须是**真实存在、可点击、内容相关**的链接；不确定是否仍有效时，先 `WebFetch` 验证。
- **主来源优先官方**：概念的解释以官方文档/论文为准，博客仅作补充与通俗化。
- **标注引用**：正文中用 `[来源 N]` 对应"参考来源"列表，便于回溯。
- **区分事实与观点**：官方事实、他人观点、本人理解要**分开写**，不混为一谈。

## 六、自检要求 (Self-check before delivery)

交付前逐条确认，**全部为"是"方可提交**：

- [ ] 概念名称明确，且资料确实围绕该概念展开？
- [ ] 9 个板块齐全（目标 / 问题 / 解释 / 机制 / 可视化讲解 / 场景 / 边界 / 自测 / 来源）？
- [ ] "个人解释"是第一人称、非照搬来源？
- [ ] 所有参考链接都是真实可点击的（未伪造）？
- [ ] 没有整段复制 AI 对话或某一来源原文？
- [ ] 应用场景是具体例子，而非空泛描述？
- [ ] "自测问题"含题型组合（简答/选择/应用）且覆盖概念辨析、机制、应用、风险四维度？
- [ ] HTML 可独立打开、无明显排版错乱？
- [ ] 若使用了 Mermaid 图，有文字说明兜底？
- [ ] "可视化讲解"板块：是否为"适合可视化"的核心概念/难点画了 1–3 张图？每张图是否都有文字/图说兜底（离线也能看懂），图中数字是否真实可溯源或已标注"示意"？

## 八、文件约定

```
.workbuddy/skills/concept-learning-generator/SKILL.md    ← 本文件
learning-materials/<slug>.html                            ← 每份概念学习资料（默认）
learning-materials/index.html                             ← 总索引（新增概念时追加一行）
learning-materials/concept-relationship.html              ← 跨概念关系说明（2+ 概念后维护）
```

每次生成新概念后：

1. 追加新文件到 `learning-materials/<slug>.html`
2. 在 `learning-materials/index.html` 表格里追加一行
3. 若已有 ≥2 个概念，提示用户是否更新 `concept-relationship.html` / `concept-relationship.md`

## 九、维护与迭代

每次用户对结果给出反馈时，回看并决定：

| 反馈 | 处理 |
|---|---|
| "太抽象 / 看不懂" | 在"个人解释"增加类比；降低术语密度 |
| "太啰嗦 / 教科书味" | 重写"个人解释"；合并要点 |
| "参考资料打不开" | 立即替换为可核查的 URL |
| "对比表不够" | 把"易混淆/边界"从 bullets 升级为对照表 |
| "图没看懂" | 检查该图是否有 `viz-caption` + 文字兜底；必要时换选型 |

每一次迭代都是对 **Skill 自身**的修订——把"什么样的概念学习资料最有用"的经验沉淀回本 SKILL.md。

> **注意**：本 Skill 面向任意概念，不要把它写成只服务于 Agent / 上下文 / Skill 三个概念的一次性提示词。新增概念时，只需提供概念名，重复 Step 1–5 即可。
