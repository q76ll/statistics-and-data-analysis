# Agent (智能体)

## 一句话定义

在大语言模型语境下，**Agent (智能体)** = 一个由 LLM 驱动的程序，它能在外部环境中**自主循环**地读取信息 → 做决策 → 调用工具/动作，直到完成给定目标或达到终止条件。

## 为什么学它

- 2024–2026 年绝大多数 LLM 应用的主形态都是 Agent：Cursor、Claude Code、Devin、Manus、各类"AI 助手"产品，背后都跑着同一个 agent loop。
- 看懂 agent loop 就能识别所有这些产品的"共同骨架"——之后无论 UI 怎么变，原理不动摇。

## 关键特征（5 条）

- **有一个明确目标**：通常以自然语言任务给出，由 Agent 自己分解、自己推进。
- **闭环循环**：感知 → 决策 → 行动 → 观察结果 → 再决策；典型实现叫 "agent loop"。
- **可调用工具**：搜索、读文件、运行代码、发请求……工具是 Agent 的"手脚"；没有工具的 Agent 退化成普通聊天机器人。
- **状态由上下文承载**：Agent 没有自己的持久记忆，短期记忆完全装在 LLM 的上下文窗口里；长期记忆落在外部存储（文件、向量库、数据库）。
- **可中断、可恢复**：因为有显式状态和中断点，Agent 天然支持失败重试、人工审批、并发分支。

## 与相近概念的对比

| 概念 | 驱动方 | 外部动作 | 典型场景 |
|---|---|---|---|
| **Agent** | LLM（自主循环） | 是 | 自主完成"做研究并写报告" |
| Chatbot | LLM（单/多轮对话） | 否 | 回答问题、不动手 |
| Workflow / Pipeline | 代码（预定流程） | 是 | 数据 ETL、CI/CD |
| Copilot | 人主导 + LLM 辅助 | 半：等人类确认 | 写代码按 Tab |

> 一句话区分：**Agent 自己决定下一步做什么**；Chatbot / Copilot 是在等人类决策；Workflow 是按预定义路径走。

## 一个具体的例子

> 场景：让 Agent "调研 GitHub 上最近 30 天最热门的 5 个 AI Agent 仓库"。
> Agent loop：(1) 调 `search_github`；(2) 观察返回 20 个仓库；(3) 决定逐个拉 README；(4) 调 `fetch_url`；(5) 调 LLM 抽取"热门原因"；(6) 写报告到本地 `report.md`。
> 用户只需说一句话、写一句话——中间过程全部自治。

## 常见误解（3 条）

- **误解：Agent = Chatbot + 搜索。** 正解：关键在**循环**。Chatbot 不会自己决定"下一步要不要再调一次搜索"。
- **误解：Agent 越多越好。** 正解：固定 pipeline 更便宜、更稳；只在"LLM 该决定下一步"时才升级为 Agent。
- **误解：Agent 会产生自我意识。** 正解：Agent 只是"循环 + 工具"，自我意识是科幻。
